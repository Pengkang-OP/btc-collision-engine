## 执行摘要

v3.0.0 引入了两项重大变更：

1. **雅可比坐标系（Jacobian Coordinates）**：消除标量乘法中的中间模逆运算
2. **MSB-first 算法修复**：修复了自 v2.4.0 起存在的严重算法逻辑错误

经端对端 GPU 性能测试验证：

- **平均吞吐量**：233,333 keys/s（含完整流水线）
- **峰值吞吐量**：250,748 keys/s
- **相对 v2.5.0 提升**：+185%（约 3x）
- **相对 CPU 加速**：2,651x
- **算法正确性**：✅ 通过（k=1→Gx，k=2→2Gx 均验证）

## 技术原理

### 1. 雅可比坐标系优化

**原始仿射坐标（v2.x）**：

- 每次 `ec_point_add` 调用 1 次 `mod_inverse`（= `mod_pow(a, P-2)` = 254 次 `mod_sqr` + ~128 次 `mod_mul` ≈ 505 次模乘）
- 每次 `ec_point_double` 同样调用 1 次 `mod_inverse`
- 每个私钥共约 338 次 `mod_inverse` 调用（31 次预计算 + 256 次倍加 + 51 次查表加）

**雅可比坐标（v3.0）**：

- `jac_point_double`：4 次 `mod_sqr` + 7 次 `mod_mul`（共 11 次，**无 mod_inverse**）
- `jac_point_add_affine`：4 次 `mod_sqr` + 12 次 `mod_mul`（共 16 次，**无 mod_inverse**）
- 整个标量乘法仅最后 `jac_to_affine` 调用 **1 次 mod_inverse**
- 模逆调用从 338 次减少到 1 次（**-99.7%**）

### 2. MSB-first 算法修复

**LSB-first 错误（v2.x）**：

```
对于 k=1（二进制 ...0001）：
  i=0: window=1, 先 5 次倍加（result=0→0），再加 G → result=G
  i=1: window=0, 5 次倍加 → result=2^5*G = 32G
  i=2: window=0, 5 次倍加 → result=2^10*G = 1024G
  ...
  最终 result = 2^(5*51)*G ≠ G   ← 错误！
```

**MSB-first 修复（v3.0）**：

```
k=1 的 256 位表示：bit255=0, ..., bit1=0, bit0=1

处理顺序（从高位到低位）：
  top_bit (bit255) = 0 → result = 无穷远点 ∞
  第 0 组 (bits 254-250) = 0 → 5次倍加，窗口=0不加点
  ...
  第 50 组 (bits 4-0) = 1 → 5次倍加，窗口=1，加 precomp[0]=G
  最终 result = 2^0 * G = G  ← 正确！
```

## 关键实现细节

### 函数接口别名安全

所有雅可比函数（`jac_point_double`、`jac_point_add_affine`）在函数入口处将输入指针拷贝到局部变量，确保即使输入输出指针相同也不会产生别名读写冲突：

```c
void jac_point_double(...) {
    // 先拷贝输入，防止别名
    uint256_t X, Y, Z;
    uint256_copy(px, &X);
    uint256_copy(py, &Y);
    uint256_copy(pz, &Z);
    // ... 计算 out_x, out_y, out_z ...
    // 最后统一写出
    uint256_copy(&out_x, rx);
    uint256_copy(&out_y, ry);
    uint256_copy(&out_z, rz);
}
```

### 边界情况处理

| 情况 | jac_point_double | jac_point_add_affine |
|------|-----------------|---------------------|
| P1 = ∞（Z=0）| 返回 ∞ | 返回 P2 |
| P1 = P2（同点）| N/A | 调用 jac_point_double |
| P1 = -P2（相反）| N/A | 返回 ∞ |
| Z = 0（jac_to_affine）| N/A | 输出 (0,0)（与代码惯例一致）|
