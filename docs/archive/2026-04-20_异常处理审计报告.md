### 问题1: SecureKeyManager.__del__ 中的裸except

**文件**: `src/core/secure_key_manager.py:261`  
**风险等级**: 🔴 **高风险**  
**影响**: 私钥可能无法安全清零

#### 当前代码
```python
def __del__(self):
    """析构函数 - 确保清零"""
    if self._key is not None and not self._cleared:
        # 尝试清零，但忽略异常（对象正在销毁）
        try:
            self.clear()
        except:  # ❌ 裸except
            pass
```

#### 风险分析
1. **捕获 KeyboardInterrupt**: 如果 `clear()` 触发 KeyboardInterrupt，会被静默吞掉
2. **捕获 SystemExit**: 阻止程序正常退出
3. **捕获 MemoryError**: 内存不足时无法正确传播异常
4. **Python 3.4+ 行为**: `__del__` 中的异常会打印到 stderr，但裸except会隐藏所有异常

#### 修复建议
```python
def __del__(self):
    """析构函数 - 确保清零"""
    if self._key is not None and not self._cleared:
        # 尝试清零，但忽略异常（对象正在销毁）
        try:
            self.clear()
        except Exception:  # ✅ 仅捕获 Exception，不捕获 BaseException
            # 析构函数中静默失败是可接受的
            # 因为此时对象正在销毁，无法做更多处理
            pass
```

#### 修复优先级: 🔴 **立即修复**
**理由**: 虽然 `__del__` 中忽略异常是合理的，但应该使用 `except Exception` 而非裸except

### 问题2: CheckpointManager 恢复断点时的裸except

**文件**: `src/collision/checkpoint_manager.py:151`  
**风险等级**: 🔴 **高风险**  
**影响**: 可能隐藏文件恢复失败的关键错误

#### 当前代码
```python
if os.path.exists(temp_filepath) and not os.path.exists(self.filepath):
    # 尝试恢复临时文件
    try:
        os.rename(temp_filepath, self.filepath)
        # 设置文件权限
        if os.name != 'nt':
            try:
                os.chmod(self.filepath, 0o600)
            except OSError:
                pass
        logger.warning(f"从临时文件恢复断点: {temp_filepath}")
    except:  # ❌ 裸except
        pass
```

#### 风险分析
1. **隐藏严重错误**: `os.rename()` 可能抛出 PermissionError、FileNotFoundError 等
2. **无法调试**: 静默失败导致无法知道断点恢复是否成功
3. **数据丢失风险**: 如果恢复失败但未记录，用户可能不知道进度丢失

#### 修复建议
```python
if os.path.exists(temp_filepath) and not os.path.exists(self.filepath):
    # 尝试恢复临时文件
    try:
        os.rename(temp_filepath, self.filepath)
        # 设置文件权限
        if os.name != 'nt':
            try:
                os.chmod(self.filepath, 0o600)
            except OSError:
                pass  # 权限设置失败不影响功能
        logger.warning(f"从临时文件恢复断点: {temp_filepath}")
    except (OSError, IOError) as e:  # ✅ 捕获文件系统异常
        logger.error(f"断点恢复失败: {e}，将重新开始")
        # 可选：删除损坏的临时文件
        try:
            os.remove(temp_filepath)
        except OSError:
            pass  # 清理失败不影响主流程
    except Exception as e:  # ✅ 兜底捕获其他异常
        logger.error(f"断点恢复未知错误: {type(e).__name__}: {e}")
```

#### 修复优先级: 🔴 **立即修复**
**理由**: 断点恢复是关键功能，失败应该被记录和告知用户

### 问题3: GPUDevice.cleanup() 中的裸except

**文件**: `src/collision/gpu_collision_engine.py:211`  
**风险等级**: 🟡 **中风险**  
**影响**: GPU 资源可能无法正确释放

#### 当前代码
```python
def cleanup(self):
    """释放资源"""
    if self.queue:
        try:
            self.queue.finish()
        except:  # ❌ 裸except
            pass
        self.queue = None
    self.context = None
    self.device = None
```

#### 风险分析
1. **清理函数特殊性**: cleanup() 函数中忽略异常是常见做法
2. **但裸except仍然危险**: 可能捕获 KeyboardInterrupt 等
3. **资源泄露风险**: 如果 finish() 失败，应该至少记录日志

#### 修复建议
```python
def cleanup(self):
    """释放资源"""
    if self.queue:
        try:
            self.queue.finish()
        except Exception as e:  # ✅ 仅捕获 Exception
            # 清理时记录调试日志，但不影响后续清理
            logger.debug(f"GPU队列清理失败: {type(e).__name__}")
        finally:
            self.queue = None  # ✅ 使用finally确保清理
    
    if self.context:
        try:
            del self.context
        except Exception as e:
            logger.debug(f"GPU上下文清理失败: {type(e).__name__}")
        finally:
            self.context = None
    
    self.device = None
```

#### 修复优先级: 🟡 **本周修复**
**理由**: 清理函数中忽略异常可接受，但应改进为 except Exception

### 问题4: GPU.is_gpu_available() 中的裸except

**文件**: `src/collision/gpu_collision_engine.py:563`  
**风险等级**: 🟡 **中风险**  
**影响**: GPU 检测失败被静默吞掉

#### 当前代码
```python
@staticmethod
def is_gpu_available() -> bool:
    """检查 GPU 是否可用"""
    if not PYOPENCL_AVAILABLE:
        return False
    try:
        devices = GPUDevice.detect_devices()
        return len(devices) > 0
    except:  # ❌ 裸except
        return False
```

#### 风险分析
1. **合理的设计意图**: 检测函数应该返回 False 而非抛出异常
2. **但裸except过度**: 应该区分预期异常和意外异常
3. **调试困难**: 无法知道是哪种异常导致检测失败

#### 修复建议
```python
@staticmethod
def is_gpu_available() -> bool:
    """检查 GPU 是否可用"""
    if not PYOPENCL_AVAILABLE:
        return False
    try:
        devices = GPUDevice.detect_devices()
        return len(devices) > 0
    except (ImportError, RuntimeError, OSError) as e:  # ✅ 捕获预期的设备检测异常
        logger.debug(f"GPU检测失败: {type(e).__name__}: {e}")
        return False
    except Exception as e:  # ✅ 兜底捕获，记录日志
        logger.warning(f"GPU检测未知错误: {type(e).__name__}: {e}")
        return False
```

#### 修复优先级: 🟡 **本周修复**
**理由**: 改进异常分类，提高可调试性

### 问题5: SQLiteStorage 加载元数据时的裸except

**文件**: `src/collision/targets/storage.py:216`  
**风险等级**: 🟡 **中风险**  
**影响**: JSON 解析失败被静默处理

#### 当前代码
```python
for key, value in cursor.fetchall():
    try:
        metadata[key] = json.loads(value)
    except:  # ❌ 裸except
        metadata[key] = value
```

#### 风险分析
1. **设计意图合理**: JSON 解析失败时回退到原始值
2. **但裸except过度**: 可能捕获 TypeError、MemoryError 等
3. **应该只捕获 JSON 解析异常**

#### 修复建议
```python
for key, value in cursor.fetchall():
    try:
        metadata[key] = json.loads(value)
    except (json.JSONDecodeError, ValueError, TypeError) as e:  # ✅ 仅捕获解析异常
        # JSON解析失败，保留原始字符串值
        logger.debug(f"元数据JSON解析失败 [{key}]: {type(e).__name__}，使用原始值")
        metadata[key] = value
```

#### 修复优先级: 🟡 **本周修复**
**理由**: 改进异常类型，避免捕获意外异常

    if self.data_logging_enabled:

## 📊 最佳实践建议

### 1. 异常捕获层次

```python
# ✅ 推荐的异常处理层次
try:
    # 业务逻辑
    pass
except (ValueError, TypeError) as e:
    # 第一层：参数错误（可预期）
    logger.error("参数错误: %s", e)
except (IOError, OSError) as e:
    # 第二层：系统错误（可预期）
    logger.error("系统错误: %s", e)
except Exception as e:
    # 第三层：未知错误（兜底）
    logger.exception("未知错误")
    # 可选择重新抛出或记录后继续
```

### 2. 禁止使用裸except的场景

- ❌ 业务逻辑处理
- ❌ 资源初始化
- ❌ 文件操作
- ❌ 网络请求
- ❌ 数据解析

### 3. 允许使用裸except的场景（极少）

- ✅ 在 `except Exception` 之后的最终兜底（仍然不推荐）
- ✅ 某些特殊框架要求（如某些测试框架）

### 4. 异常信息安全性

```python
# ❌ 泄露敏感信息
except Exception as e:
    logger.error(f"私钥生成失败: {private_key}, 错误: {e}")

# ✅ 安全做法
except Exception as e:
    logger.error(f"私钥生成失败 (尝试 {attempt}/{max_retries}): {type(e).__name__}")
```
