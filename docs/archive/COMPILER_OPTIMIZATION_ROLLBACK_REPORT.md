## [SEARCH] 问题分析

### 1. 性能下降12.2%

**可能原因**:

#### A. 快速数学运算引入精度问题

```python
'use_fast_math': True  # ← 可能导致精度损失
```

**影响**:

- BTC地址碰撞需要精确的椭圆曲线运算
- 快速数学可能改变了运算顺序
- 导致额外的校验或重试

#### B. 不安全的数学优化

```python
'compiler_flags': '-cl-fast-relaxed-math -cl-unsafe-math-optimizations'
```

**问题**:

- `-cl-unsafe-math-optimizations` 可能破坏加密运算的正确性
- SHA256/RIPEMD160哈希对精度敏感
- 椭圆曲线点乘需要高精度

### 2. 稳定性严重恶化 (CV 0.11% → 19.85%)

**症状**:

```
最低速度: 16,845.10 keys/s  (正常应为43k+)
变异系数: 19.85%  (正常应<1%)
```

**分析**:

- 速度波动极大（16k - 38k）
- 某些批次性能严重下降
- 可能存在：
  - 内核编译不稳定
  - 精度校验重试
  - 错误处理开销

### 3. 初始化时间异常

**优化前**: 947-965ms  
**优化后**: 829ms  

**说明**:

- 初始化更快（可能是内核编译更快）
- 但运行时性能更差
- 表明优化标志改变了内核执行方式

## [TARGET] 根本原因

### 主要问题: 编译器优化不适用于加密运算

**BTC地址碰撞的核心运算**:

1. **椭圆曲线点乘** (secp256k1)
   - 需要精确的模运算
   - 对精度要求极高
   - 快速数学可能破坏正确性

2. **SHA256哈希**
   - 位操作敏感
   - 需要精确的整数运算
   - 不安全优化可能导致错误

3. **RIPEMD160哈希**
   - 同样对精度敏感
   - 不适当的优化会破坏结果

### 编译器优化标志的问题

| 标志 | 作用 | 对加密运算的影响 |
|------|------|----------------|
| `-cl-fast-relaxed-math` | 放宽数学精度 | [CROSS] 破坏模运算精度 |
| `-cl-unsafe-math-optimizations` | 不安全优化 | [CROSS] 改变运算顺序 |

**结论**:
这些优化标志适用于**浮点密集的科学计算**，但不适用于**加密/哈希运算**。
