## ⚠️ 发现的关键问题

### 🔴 P0 - 严重错误（必须修复）

#### 问题1: 算法实现不是真正的w-NAF，而是简单窗口法

**严重程度**: 🔴 高  
**位置**: kernel.py 第480-557行  
**问题类型**: 算法正确性

**问题描述**:

代码注释声称是"w-NAF窗口优化算法"，但实际实现的是**简单窗口法（Simple Window Method）**，而非w-NAF（Width-w Non-Adjacent Form）。

**当前实现（简单窗口法）**:

```c
for (int i = 0; i < 64; i++) {
    int window = exp.d[0] & 0xF;  // 简单提取4位 (0-15)
    
    // 4次点倍加
    for (int j = 0; j < 4; j++) {
        ec_point_double(&result_x, &result_y, &temp2x, &temp2y);
    }
    
    // 如果window是偶数(2,4,6,8,10,12,14)，映射会出错！
    if (window > 0) {
        int index = (window - 1) / 2;  // window=2 → index=0 (错误！应该是2G)
        
        if (index >= 0 && index < 4) {
            ec_point_add(..., &precomp_x[index], ...);  // 错误映射
        }
    }
}
```

**错误分析**:

预计算表只包含**奇数倍**点：`[1G, 3G, 5G, 7G]`

但当窗口值为**偶数**时：

- `window = 2` → `index = (2-1)/2 = 0` → 使用`1G` ❌（应该是`2G`）
- `window = 4` → `index = (4-1)/2 = 1` → 使用`3G` ❌（应该是`4G`）
- `window = 6` → `index = (6-1)/2 = 2` → 使用`5G` ❌（应该是`6G`）
- `window = 8` → `index = (8-1)/2 = 3` → 使用`7G` ❌（应该是`8G`）
- `window = 10,12,14` → `index >= 4` → 被过滤掉 ❌

**影响范围**:

- 约50%的私钥计算会出错（窗口值为偶数时）
- 导致公钥计算错误
- **私钥碰撞完全失败**

**修复方案**:

**方案A: 使用真正的w-NAF编码**（推荐）

```c
// w-NAF编码确保窗口值总是奇数
for (int i = 0; i < 64; i++) {
    int window = exp.d[0] & 0xF;
    
    // 如果是偶数，需要特殊处理
    if (window % 2 == 0) {
        // 选项1: 逐位处理这个窗口
        for (int bit = 0; bit < 4; bit++) {
            ec_point_double(&result_x, &result_y, &temp2x, &temp2y);
            if ((window >> (3-bit)) & 1) {
                ec_point_add(&result_x, &result_y, gx, gy, &temp2x, &temp2y);
                uint256_copy(&temp2x, &result_x);
                uint256_copy(&temp2y, &result_y);
            }
        }
    } else {
        // 奇数，使用预计算表
        int index = (window - 1) / 2;
        // 4次点倍加
        for (int j = 0; j < 4; j++) {
            ec_point_double(&result_x, &result_y, &temp2x, &temp2y);
            uint256_copy(&temp2x, &result_x);
            uint256_copy(&temp2y, &result_y);
        }
        ec_point_add(&result_x, &result_y, &precomp_x[index], &precomp_y[index], &temp2x, &temp2y);
        uint256_copy(&temp2x, &result_x);
        uint256_copy(&temp2y, &result_y);
    }
    
    exp >>= 4;
}
```

**方案B: 扩大预计算表**（更简单，但占用更多内存）

```c
// 预计算所有可能的值: [1G, 2G, 3G, ..., 15G]
uint256_t precomp_x[15], precomp_y[15];

// 预计算1G-15G
uint256_copy(gx, &precomp_x[0]);
uint256_copy(gy, &precomp_y[0]);

for (int i = 1; i < 15; i++) {
    ec_point_add(&precomp_x[i-1], &precomp_y[i-1], gx, gy, &temp2x, &temp2y);
    uint256_copy(&temp2x, &precomp_x[i]);
    uint256_copy(&temp2y, &precomp_y[i]);
}

// 使用时直接映射
if (window > 0) {
    int index = window - 1;  // window: 1-15 → index: 0-14
    ec_point_add(&result_x, &result_y, &precomp_x[index], &precomp_y[index], ...);
}
```

**建议**: 使用**方案B**，因为：

1. 实现简单，不易出错
2. 性能更好（不需要特殊分支）
3. 内存开销可接受（15个点 vs 4个点）

#### 问题2: 预计算7G的计算有误

**严重程度**: 🔴 高  
**位置**: kernel.py 第508-512行

**问题代码**:

```c
// 预计算: precomp[3] = 7G = 2*(3G) + G
ec_point_double(&precomp_x[1], &precomp_y[1], &temp2x, &temp2y);  // 6G = 2*3G
ec_point_add(&temp2x, &temp2y, gx, gy, &precomp_x[3], &precomp_y[3]);  // 7G = 6G + G
uint256_copy(&precomp_x[3], &precomp_x[3]);  // ❌ 无意义的自我拷贝
uint256_copy(&precomp_y[3], &precomp_y[3]);  // ❌ 无意义的自我拷贝
```

**问题**:

1. 最后两行是**无意义的自我拷贝**，浪费时间
2. 应该删除或改为其他用途

**修复**:

```c
// 预计算: precomp[3] = 7G = 2*(3G) + G
ec_point_double(&precomp_x[1], &precomp_y[1], &temp2x, &temp2y);  // 6G = 2*3G
ec_point_add(&temp2x, &temp2y, gx, gy, &precomp_x[3], &precomp_y[3]);  // 7G = 6G + G
// 删除自我拷贝
```

#### 问题5: 窗口大小可能不是最优

**严重程度**: 🟢 低  
**位置**: kernel.py 第524行

**分析**:

当前使用w=4，但可以考虑：

- **w=3**: 预计算4个点 [1G, 3G, 5G, 7G]（当前）
- **w=4**: 预计算8个点 [1G, 3G, ..., 15G]

**权衡**:

- 更大的w：更少的点加，更多的预计算和内存
- 更小的w：更多的点加，更少的预计算和内存

**建议**:

- 测试w=4和w=5的性能
- 选择最优的窗口大小
