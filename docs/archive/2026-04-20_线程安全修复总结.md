## 1. 碰撞引擎多锁死锁风险修复

### 1.1 问题描述

**位置**: `src/collision/key_collision_engine.py`

**原始设计**:
```python
# 三个独立的锁
self._count_lock = threading.Lock()    # 保护计数器
self._matches_lock = threading.Lock()  # 保护匹配列表（未使用）
self._dedup_lock = threading.Lock()    # 保护去重过滤器（未使用）
```

**风险**:
- `_matches_lock`和`_dedup_lock`已不再使用（历史遗留代码）
- 多锁设计存在潜在的锁顺序不一致风险
- 如果未来代码以不同顺序获取多个锁，可能导致死锁

### 1.2 修复方案

**简化为单锁设计**:
```python
# 修复后：单一状态锁
# 注意：已简化为单锁设计，避免多锁导致的死锁风险
# _state_lock 保护所有共享状态（计数器、位置、模式等）
self._state_lock = threading.Lock()
```

**修改内容**:
- 移除未使用的`_matches_lock`和`_dedup_lock`
- 将`_count_lock`重命名为`_state_lock`（更准确的语义）
- 更新所有使用`_count_lock`的地方为`_state_lock`（共8处）

## 2. 配置管理器线程安全修复

### 2.1 问题描述

**位置**: `src/config/config_manager.py`

**原始设计**:
```python
class ConfigManager:
    def __init__(self, config_file: str = None):
        self.config_file = config_file
        self.config = self.DEFAULT_CONFIG.copy()
        # 缺少锁保护
    
    def get(self, key: str, default: Any = None) -> Any:
        # 无锁读取
        value = self.config
        # ...
    
    def set(self, key: str, value: Any) -> bool:
        # 无锁写入
        config = self.config
        # ...
```

**风险**:
- 多线程同时读取可能返回不一致的状态
- 多线程同时写入可能导致配置丢失
- 读写并发可能导致数据结构损坏

### 2.2 修复方案

**添加完整的线程安全保护**:

```python
class ConfigManager:
    def __init__(self, config_file: str = None):
        self.config_file = config_file
        self.config = self.DEFAULT_CONFIG.copy()
        self._lock = threading.Lock()  # 线程锁保护配置读写
    
    def load_config(self) -> bool:
        """从文件加载配置（线程安全）"""
        try:
            with open(self.config_file, 'r', encoding='utf-8') as f:
                user_config = json.load(f)
            # 线程安全：在锁内合并配置
            with self._lock:
                self._merge_config(self.config, user_config)
            return True
        except Exception as e:
            logger.error(f"加载配置文件失败: {e}")
            return False
    
    def save_config(self) -> bool:
        """保存配置到文件（线程安全）"""
        if not self.config_file:
            return False
        
        try:
            # 线程安全：在锁内复制配置，避免长时间持有锁
            with self._lock:
                config_copy = self._deep_copy_config(self.config)
            
            with open(self.config_file, 'w', encoding='utf-8') as f:
                json.dump(config_copy, f, ensure_ascii=False, indent=2)
            return True
        except Exception as e:
            logger.error(f"保存配置文件失败: {e}")
            return False
    
    def get(self, key: str, default: Any = None) -> Any:
        """获取配置值（线程安全）"""
        keys = key.split('.')
        # 线程安全：在锁内读取配置
        with self._lock:
            value = self.config
        
        for k in keys:
            if isinstance(value, dict) and k in value:
                value = value[k]
            else:
                return default
        
        return value
    
    def set(self, key: str, value: Any) -> bool:
        """设置配置值（线程安全）"""
        keys = key.split('.')
        # 线程安全：在锁内修改配置
        with self._lock:
            config = self.config
            
            for i, k in enumerate(keys[:-1]):
                if k not in config or not isinstance(config[k], dict):
                    config[k] = {}
                config = config[k]
            
            config[keys[-1]] = value
        return True
    
    def _deep_copy_config(self, config: Dict) -> Dict:
        """深拷贝配置字典（避免在写文件时持有锁）"""
        import copy
        return copy.deepcopy(config)
```

## 5. 最佳实践总结

### 5.1 锁设计原则

1. **最小化锁数量**
   - 优先使用单锁设计
   - 避免多锁导致的死锁风险
   - 如果必须使用多锁，统一获取顺序

2. **最小化锁持有时间**
   - 在锁内只执行必要的操作
   - 文件I/O、网络I/O等慢操作应在锁外执行
   - 使用深拷贝避免长时间持有锁

3. **使用上下文管理器**
   - 始终使用`with`语句管理锁
   - 确保异常情况下锁能正确释放

### 5.2 线程安全测试要点

1. **并发访问测试**
   - 多个线程同时读写共享资源
   - 验证无异常和数据不一致

2. **压力测试**
   - 大量线程 x 大量迭代
   - 验证无死锁和性能可接受

3. **边界条件测试**
   - 测试极端情况（空配置、大配置等）
   - 验证异常处理正确
