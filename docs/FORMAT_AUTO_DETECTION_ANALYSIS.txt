================================================================================
三、格式匹配限制
================================================================================

假设目标地址是不同格式，系统行为如下:

| 目标地址格式 | 引擎生成地址 | 能否匹配? | 原因 |
|-------------|------------|----------|------|
| P2PKH (1xxx) | P2PKH (1xxx) | ✓ 可以 | 格式相同 |
| P2SH (3xxx) | P2PKH (1xxx) | ✗ 无法 | 格式不同，Hash160不同 |
| Bech32 (bc1q) | P2PKH (1xxx) | ✗ 无法 | 格式不同，Hash160不同 |
| Taproot (bc1p) | P2PKH (1xxx) | ✗ 无法 | 格式不同，Hash160不同 |

原因解释:
  - P2PKH: Hash160(公钥) → 版本0x00 → Base58Check
  - P2SH: Hash160(redeem_script) → 版本0x05 → Base58Check
  - Bech32: Hash160(公钥) → witness_program → Bech32编码
  - Taproot: xonly公钥 → witness_program → Bech32m编码

  即使是同一个公钥，不同格式的地址也完全不同！

================================================================================
四、技术原因分析
================================================================================

1. 密码学哈希特性
   - 不同的输入 → 不同的哈希值
   - P2PKH: HASH160(公钥)
   - P2SH: HASH160(redeem_script)，而redeem_script ≠ 公钥
   - Bech32: witness_program = HASH160(公钥)，但编码方式不同

2. 地址编码差异
   - P2PKH/P2SH: Base58Check编码
   - Bech32: Bech32编码 (BIP-173)
   - Taproot: Bech32m编码 (BIP-350)

3. 版本字节不同
   - P2PKH: 0x00
   - P2SH: 0x05
   - Bech32: 无版本字节，使用witness version
   - Taproot: 无版本字节，使用witness version

五、解决方案建议
================================================================================

要实现"根据目标地址格式自动生成对应格式"的功能，需要:

方案1: 扩展目标解析器 (推荐)
  1. 检测目标地址格式
  2. 为不同格式创建不同的目标集合
  3. 根据格式生成对应的地址
  4. 与对应格式的目标集合匹配

  实现示例:
  ```python
  # 检测格式
  format = detect_address_format(target_address)

  # 根据格式生成地址
  if format == "P2PKH":
      address = generate_p2pkh_address(private_key)
  elif format == "P2SH":
      address = generate_p2sh_address(private_key)
  elif format == "Bech32":
      address = generate_bech32_address(private_key)
  elif format == "Taproot":
      address = generate_taproot_address(private_key)

  # 与对应格式目标匹配
  if address == target_address:
      found_match()
  ```

方案2: 多引擎并行
  - P2PKH引擎: 生成P2PKH地址，匹配1开头目标
  - P2SH引擎: 生成P2SH地址，匹配3开头目标
  - Bech32引擎: 生成Bech32地址，匹配bc1q开头目标
  - Taproot引擎: 生成Taproot地址，匹配bc1p开头目标

  优点: 引擎独立，易于扩展
  缺点: 计算资源增加

方案3: 智能混合引擎
  - 自动检测所有目标地址格式
  - 一次性生成所有格式的地址
  - 同时与所有格式的目标匹配
  - 找到任意格式匹配即报告

  实现示例:
  ```python
  # 一次性生成所有格式
  addresses = {
      "p2pkh": generate_p2pkh_address(private_key),
      "p2sh": generate_p2sh_address(private_key),
      "bech32": generate_bech32_address(private_key),
      "taproot": generate_taproot_address(private_key),
  }

  # 同时匹配所有格式目标
  for format, address in addresses.items():
      if address in targets[format]:
          report_match(format, address, private_key)
  ```

七、当前系统的使用建议
================================================================================

1. 目标地址格式选择
   - ✓ 仅使用P2PKH格式目标地址 (1开头)
   - ✗ 避免使用P2SH/Bech32/Taproot目标
   - ✓ 目标文件只包含有效的P2PKH地址

2. 格式验证
   - 使用BitcoinKeyValidator验证目标地址格式
   - 确保所有目标都是P2PKH格式
   - 过滤掉非P2PKH格式的目标

3. 目标文件准备
   ```bash
   # 检查目标文件中的地址格式
   grep -v "^1" targets.txt  # 找出非P2PKH地址
   grep "^1" targets.txt > p2pkh_only.txt  # 只保留P2PKH地址
   ```

九、结论
================================================================================

当前系统状态:
  ✗ 不支持格式自动检测
  ✗ 只生成P2PKH地址
  ✗ 非P2PKH目标无法匹配

技术原因:
  - 密码学哈希不可逆，不同输入产生不同哈希
  - 不同地址格式使用不同的哈希和编码
  - 引擎设计为单一格式 (P2PKH)

建议行动:
  1. 短期: 使用P2PKH格式目标地址
  2. 中期: 实现方案1 (扩展目标解析器)
  3. 长期: 实现方案3 (智能混合引擎)
