## 功能概述

BTC私钥对撞工具的GUI界面现已完整支持断点续传和恢复功能，允许用户：

- 在对撞过程中保存进度

- 从上次停止的位置继续对撞

- 查看断点状态信息

- 手动恢复断点

## 功能特性

### 1. 断点续传复选框

**位置**: 控制面板 -> 高级选项区

**功能**:

- 启用后，对撞过程会自动保存进度（默认30秒间隔）

- 启用时如果检测到现有断点，会显示断点信息提示

- 开始对撞时如果存在断点，会询问用户是否从断点继续

**操作流程**:

1. 勾选"断点续传"复选框

2. 如果存在断点文件，会显示断点信息（模式、已检测数量、保存时间）

3. 点击"开始对撞"

4. 如果存在断点，弹出对话框询问：

   - 选择【是】：从断点继续

   - 选择【否】：开始新的对撞（断点文件将被覆盖）

### 2. 恢复断点按钮

**位置**: 控制面板 -> 高级选项区

**功能**:

- 点击后检查是否存在断点文件

- 显示断点详细信息

- 确认后从断点恢复对撞

**操作流程**:

1. 点击"恢复断点"按钮

2. 系统显示断点信息：

   - 模式（random/range/brute_force）

   - 目标地址数量

   - 已检测数量

   - 保存时间

3. 确认恢复后，系统会：

   - 加载目标地址

   - 创建对撞引擎（支持CPU/GPU）

   - 从上次进度继续对撞

### 3. 断点状态显示

**位置**: 控制面板 -> 高级选项区 -> 恢复断点按钮右侧

**显示内容**:

- [OK] 有断点：显示 `[OK] 断点: 8,126,464 (random)`（绿色）

- [FAIL] 断点无效：显示 `[FAIL] 断点文件无效`（红色）

- 无断点：显示 `无断点`（青色）

**更新时机**:

- GUI初始化时

- 切换断点续传复选框时

- 对撞完成/停止后

## 技术实现

### CheckpointManager 类

**文件**: `src/collision/checkpoint_manager.py`

**核心方法**:

- `save()`: 保存断点到JSON文件（线程安全）

- `load()`: 从文件加载断点

- `exists()`: 检查断点文件是否存在

- `delete()`: 删除断点文件

- `should_auto_save()`: 检查是否需要自动保存

**安全特性**:

- 使用临时文件 + 原子重命名，防止写入中断导致文件损坏

- 线程锁保护文件操作

- 自动清理敏感信息（不保存私钥）

- 仅保存地址和时间戳用于统计

### GUI 集成

**文件**: `key_collision_gui.py`

**关键组件**:

- `ControlPanel._on_checkpoint_toggled()`: 处理断点续传复选框切换

- `ControlPanel._on_resume_checkpoint()`: 处理恢复断点按钮点击

- `ControlPanel._update_checkpoint_status()`: 更新断点状态显示

- `CollisionGUI._on_resume_from_control_panel()`: 执行断点恢复逻辑

- `CollisionGUI._on_start()`: 开始对撞时检查断点

## 使用场景

### 场景1: 长时间对撞任务

1. 设置目标地址和对撞参数

2. 勾选"断点续传"

3. 开始对撞

4. 系统每30秒自动保存进度

5. 如需停止，点击"停止"按钮

6. 下次启动GUI时，点击"恢复断点"继续

### 场景2: 意外中断恢复

1. 程序意外关闭或系统重启

2. 重新启动GUI

3. 点击"恢复断点"按钮

4. 确认断点信息后继续对撞

### 场景3: 切换对撞模式

1. 完成一次对撞后

2. 修改目标地址或模式

3. 如果勾选"断点续传"，系统会询问是否覆盖现有断点

4. 选择开始新的对撞或从断点继续

## 注意事项

1. **安全性**: 断点文件不包含私钥信息，仅保存地址和统计信息

2. **文件位置**: 断点文件保存在 `src/collision/collision_checkpoint.json`

3. **自动保存间隔**: 默认30秒，可在CheckpointManager初始化时修改

4. **版本兼容**: 断点文件版本为1，未来版本可能需要迁移

5. **磁盘空间**: 大量目标地址会增加断点文件大小

## 故障排除

### 问题1: "未找到断点文件"

- **原因**: 从未保存过断点或断点文件被删除

- **解决**: 开始新的对撞并启用断点续传

### 问题2: "断点文件加载失败或格式不兼容"

- **原因**: 断点文件损坏或版本不匹配

- **解决**: 删除断点文件，开始新的对撞

### 问题3: 断点状态显示不正确

- **原因**: 断点文件被外部修改

- **解决**: 点击"恢复断点"按钮重新加载
