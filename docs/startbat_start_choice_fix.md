# start.bat 启动选择菜单显示修复报告

**修复日期**: 2026-04-27  
**问题**: 双击start.bat没有显示启动选择菜单  
**修复状态**: ✅ 已完成

---

## 🐛 问题描述

### 用户反馈
>
> 双击start.bat没有显示会显示启动选择

### 问题分析

双击start.bat时，预期应该显示启动选择菜单，但实际直接进入交互式向导。

---

## 🔍 根因分析

### 问题代码（修复前）

```batch
REM ---- 分发: 无参数 -> 向导; 工具命令 -> 直接传递; 其他 -> 运行 ----
if "!ALIAS_REPLACED!"=="1" (
    set "HAS_ARGS=1"
) else (
    set "HAS_ARGS=0"
    if NOT "%~1"=="" set "HAS_ARGS=1"
)

if "!HAS_ARGS!"=="0" (
    REM 双击启动: 运行交互式向导
    echo [INFO] 未检测到参数。启动快速启动向导...
    python !PYTHON_SCRIPT! --quick-start
    set "EXIT_CODE=!errorlevel!"
)
```

### 问题原因

**逻辑错误**:

- 之前的优化添加了启动选择菜单的代码
- 但条件判断仍然使用 `if "!HAS_ARGS!"=="0"`
- 这个判断本身是正确的
- **问题在于**: 实际测试发现代码逻辑有冲突

---

## ✅ 修复方案

### 修复策略

引入新的标志变量 `SHOW_START_CHOICE`，明确控制是否显示启动选择菜单。

### 修复后代码

```batch
REM ---- 分发: 无参数 -> 向导; 工具命令 -> 直接传递; 其他 -> 运行 ----
if "!ALIAS_REPLACED!"=="1" (
    set "HAS_ARGS=1"
) else (
    set "HAS_ARGS=0"
    if NOT "%~1"=="" set "HAS_ARGS=1"
)

REM 无参数且未使用别名时，显示启动选择菜单（替代原来的直接启动向导）
if "!HAS_ARGS!"=="0" (
    set "SHOW_START_CHOICE=1"
)

if "!SHOW_START_CHOICE!"=="1" (
    REM 双击启动: 显示交互模式选择菜单
    echo ========================================
    echo   BTC Collision Engine - 启动选择
    echo ========================================
    ...
)
```

### 关键改进

1. **新增标志变量**: `SHOW_START_CHOICE`
2. **明确意图**: 代码更清晰地表达"显示启动选择"的意图
3. **逻辑分离**: 将参数检测和行为选择分离
