2
目标地址解析层 (TargetResolver)
🔍 格式检测 (detect_format)
智能识别规则
• P2PKH: startswith('1') + 25-34字符
• P2SH: startswith('3') + 25-34字符
• WIF: '5'(51字符) 或 'K'/'L'(52字符)
• 压缩公钥: 66字符 + 02/03前缀
🔄 格式转换 (resolve)
统一转换为P2PKH地址
• P2SH: 提取Hash160 → 0x00版本编码
• WIF: 解码 → 椭圆曲线推导 → 地址
• 公钥: Hash160 → Base58Check
• Hash160: 直接Base58Check编码
⚡ LRU缓存优化
缓存机制
• 默认容量: 10,000条目
• 命中率统计: 启用
• 批量解析优化: 100行/批

缓存查询流程

输入地址 → 检查缓存 → 命中? 返回 → 未命中? 解析 → 存入缓存

高效匹配引擎 (AddressMatcher)
🎯 三种匹配策略

Hash Set (默认)

适用: <10万地址

时间: O(1) 查找

空间: O(n×50字节)

误判: 0%

Bloom Filter

适用: ≥10万地址

时间: O(k) 查找

空间: O(n/8字节) ↓98%

误判: 0.1%可配置

Trie 前缀树

适用: 前缀匹配

时间: O(m) 查找

空间: O(n×m)

特性: 模式匹配

⚙️ 核心架构
数据结构

🔎 O(1) 匹配机制
批量检查流程
1. 提取 addr_info['hash160']
2. target_table.check_match(hash160)
3. 字典查找: hash160 → 目标信息
4. 匹配成功记录完整信息
